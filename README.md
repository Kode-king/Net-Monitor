# net-monitor — مراقبة السيرفرات والسويتشات والراوترات عبر SNMP

لوحة مراقبة مبنية على **Next.js (JavaScript) + Tailwind** تجمع مقاييس الأداء (CPU / RAM / التخزين / حركة الشبكة / مدة التشغيل) من أجهزتك عبر **SNMP v1 / v2c / v3**، وتخزّنها في قاعدة بيانات SQLite محلية، وتعرضها في رسوم بيانية زمنية مع نظام تنبيهات وصلاحيات مستخدمين.

## المتطلبات
- Node.js 18+ (مثبت لديك: v24)
- أجهزة تدعم SNMP ومفعّل عليها (community string + UDP/161 مفتوح تجاه السيرفر)

## التشغيل محليًا

```bash
cd net-monitor
npm install
npm run dev
```

- افتح: http://localhost:4000
- الحساب الافتراضي: **admin / admin** — غيّر كلمة المرور من صفحة الإعدادات فورًا.

المتغيّر `RUN_POLLER_IN_APP=1` في `.env.local` يشغّل خدمة الاستعلام (poller) داخل تطبيق Next أثناء التطوير.

## التشغيل في الإنتاج

```bash
npm run build
npm run start                 # الواجهة على المنفذ 4000
# في عملية منفصلة (وأزل RUN_POLLER_IN_APP من البيئة):
npm run poller                # خدمة استعلام SNMP المستمرة
```

يفضّل تشغيل `poller` كخدمة مستقلة (systemd / PM2 / Windows Service) لأنها تحتاج للعمل باستمرار.

## الإعداد
1. سجّل الدخول ثم **الأجهزة ← إضافة جهاز**.
2. أدخل الاسم، العنوان/IP، النوع (سيرفر/سويتش/راوتر)، وإصدار SNMP:
   - **v1 / v2c**: community string.
   - **v3**: اسم المستخدم (Security Name)، مستوى الأمان (noAuthNoPriv / authNoPriv / authPriv)،
     بروتوكول ومفتاح المصادقة (MD5/SHA/SHA-2)، وبروتوكول ومفتاح التشفير (DES/AES) عند authPriv،
     و Context اختياريًا.
3. اضغط **اختبار SNMP** للتأكد من الوصول قبل الحفظ.
4. عدّل قواعد التنبيه من **الإعدادات** (توجد قواعد افتراضية: توقف الجهاز، CPU>90%، RAM>90%، التخزين>90%).

## المقاييس المدعومة (OIDs)
- النظام: `sysName`, `sysDescr`, `sysUpTime`
- المعالج: `HOST-RESOURCES hrProcessorLoad` ثم fallback إلى Cisco `cpmCPUTotal5min`
- الذاكرة/التخزين: `hrStorageTable` (RAM + Fixed Disks) ثم fallback إلى Cisco memory pool
- الشبكة: `ifName / ifOperStatus / ifHCInOctets / ifHCOutOctets / ifHighSpeed` (تُحسب السرعة bps بين كل استعلامين)

## البنية
```
app/                واجهة Next (App Router)
  (dash)/           الصفحات المحمية: الرئيسية، الأجهزة، التنبيهات، الإعدادات
  api/              مسارات REST
lib/
  db.js             اتصال SQLite + المخطط
  snmp.js           جلب المقاييس عبر net-snmp
  poller.js         حلقة الاستعلام + تقييم التنبيهات + تنظيف البيانات
  auth.js           جلسات JWT عبر cookie + bcrypt
  queries.js        استعلامات القراءة للـ API
scripts/
  standalone-poller.mjs
data/net-monitor.db  قاعدة البيانات (تُنشأ تلقائيًا)
```

## التنبيهات الحرجة (بريد + صفارة إنذار)

- كل قاعدة تنبيه لها **خطورة**: `تحذير` أو `حرج جدًا` (تُضبط من **الإعدادات ← قواعد التنبيه**).
- عند إطلاق تنبيه **حرج جدًا**:
  - **صفارة إنذار في المتصفح** + شريط أحمر أسفل الصفحة لكل من يفتح اللوحة (زر "كتم الصوت" متاح).
  - **رسالة بريد** للمستقبلين المحدَّدين في **الإعدادات ← الإشعارات**.
- إعداد خادم البريد في `.env.local` (خادم SMTP الداخلي للمستشفى):
  ```
  SMTP_HOST=mail.hospital.local
  SMTP_PORT=25
  SMTP_FROM=net-monitor@hospital.local
  # SMTP_USER= / SMTP_PASS=  عند الحاجة، SMTP_SECURE=1 لمنفذ 465
  ```
  اترك `SMTP_HOST` فارغًا لتعطيل البريد (تبقى صفارة المتصفح تعمل). استخدم زر **إرسال رسالة اختبار** للتأكد.

## التقرير الدوري بالبريد

من **الإعدادات ← الإشعارات ← التقرير الدوري بالبريد**: فعّله واختر اليوم والساعة وفترة التقرير (افتراضيًا كل أسبوع، 7 أيام).
يُرسَل تقرير جدولي عن **كل الأجهزة** يشمل: نسبة التوفّر، متوسط/ذروة المعالج، الذاكرة، أقصى استخدام تخزين، عدد التنبيهات (والحرجة منها)، والحالة الحالية — لنفس قائمة الإيميلات. زر **إرسال التقرير الآن** لاختباره فورًا. الجدولة يتولّاها الـ poller، فلازم يكون شغّالًا.

## الأمان

المُطبَّق في التطبيق:
- جلسات JWT عبر cookie فقط (`httpOnly`, `sameSite=lax`, و`Secure` عند `COOKIE_SECURE=1`)، كلمات المرور bcrypt.
- **تحديد محاولات الدخول**: 8 محاولات/دقيقة لكل IP ولكل مستخدم ثم قفل 15 دقيقة.
- **سياسة كلمة المرور**: 12 حرفًا على الأقل مع حروف وأرقام.
- **تشفير الأسرار**: community strings ومفاتيح SNMPv3 تُشفَّر في قاعدة البيانات (AES-256-GCM بمفتاح من `AUTH_SECRET` أو `SECRET_KEY`). القيم القديمة تبقى تعمل وتُشفَّر عند أول حفظ.
- **ترويسات أمان**: CSP، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy: no-referrer`، HSTS.
- **حماية CSRF**: فحص `Origin` لكل طلب تعديل.
- **سجل تدقيق**: كل الأحداث الحساسة (دخول/فشل/قفل، تغيير مستخدمين/أجهزة/إعدادات) في **الإعدادات ← سجل التدقيق**.

مطلوب منك:
- `AUTH_SECRET` سلسلة عشوائية ≥ 32 حرفًا (انظر `.env.example`).
- شغّل خلف HTTPS (reverse proxy) واضبط `COOKIE_SECURE=1`.
- SNMPv3 بمستوى **authPriv** للسويتشات والراوترات؛ v1/v2c داخل شبكة موثوقة فقط.
- صلاحيات ملف `data/net-monitor.db` لمستخدم الخدمة فقط، ونسخ احتياطي مشفّر.

راجع **دليل النشر في الداتا سنتر** للتفاصيل الكاملة.
